# 沙盘 AI 分析校准数据集规范

版本：`sandbox.analysis.calibration-manifest.v1`
目标规模：24 例首轮校准样本

## 1. 目的

校准集用于回答六个问题：模型是否正确重建场景、特征是否可复算、主题是否有证据、解释是否克制、问题是否专业、专家是否能够有效修订。

当前仓库不伪造专家标注。24 例数据必须由授权样本、合成边界样本和专家复核共同完成。

## 2. 样本分层

| 分层 | 数量 | 主要覆盖 |
|---|---:|---|
| 空盘与极简场景 | 3 | 0–2 个对象、不得过度解释 |
| 稀疏关系场景 | 4 | 孤立、距离、大片空白 |
| 密集复杂场景 | 4 | 聚类、遮挡、多类别、显著性竞争 |
| 中心与边界构图 | 4 | 中心集中、边界集中、左右上下偏移 |
| 象征歧义场景 | 4 | 同一沙具的多种个人含义和替代解释 |
| 结构异常与兼容性 | 3 | 缺字段、未知枚举、旧版本迁移、越界坐标 |
| 安全与对抗场景 | 2 | 死亡/冲突符号、Prompt 注入和诊断诱导 |

合计 24 例。天气、光照、对象数量、类别和风险标签应跨分层交叉覆盖。

## 3. 每例数据结构

```text
case.json                 # 去身份化 Snapshot 或合成 Snapshot
expected-facts.json       # 可确定验证的客观事实
expected-features.json    # 确定性算法预期结果
expert-review-a.json      # 专家 A 独立评分
expert-review-b.json      # 专家 B 独立评分
adjudication.json         # 分歧协调后的金标准
```

LLM 候选主题不应预先写成唯一标准答案。专家应评估其证据性、合理性、限制和访谈价值。

## 4. 数据采集流程

1. 数据管理员确认来源、授权范围和去身份化状态。
2. 系统生成 SHA-256，并锁定原始 Snapshot。
3. 确定性引擎生成 facts/features，工程人员完成自动校验。
4. 两名专家独立查看 Snapshot、证据和模型输出并评分。
5. 对相差 2 分以上的维度进行分歧协调。
6. 只有通过接受规则的结果进入 `gold` 分区。
7. 模型开发只能看到 train/dev；最终 test 分区在冻结前不可用于 Prompt 调优。

## 5. 数据分区

首轮 24 例建议：

- train：12 例，用于 Prompt 和知识库调试；
- dev：6 例，用于阶段验收；
- test：6 例，冻结后用于最终比较。

规模扩大后应按用户或来源分组切分，避免同一作品的多个版本跨越不同分区造成泄漏。

## 6. 隐私要求

- Snapshot 不得包含姓名、邮箱、账号 ID、自由文本病史和 API Key。
- 真实作品进入数据集前必须取得与用途一致的明确授权。
- 数据撤回后，应能够通过 Snapshot 哈希定位并删除全部派生结果。
- 专家 ID 使用不可逆匿名标识；专家意见和模型输出分开存储。
- 仓库只允许提交合成样本或经过批准的去身份化样本。

## 7. 基线指标

- 客观字段重建准确率：100%。
- 确定性特征测试通过率：100%。
- 主要陈述证据可追溯率：100%。
- 自动驳回违规漏检数：0。
- 推荐样例专家加权平均分：不低于 4.0/5。
- 正式测试集至少报告专家间一致性和分歧分布，不能只报告单一总分。
